## 一、這條線是什麼(一句話)

**一個人用 AI 輔助工具(Claude Code 當開發主力)從零建一個對外收費的 SaaS/App,
上線後靠短影音 + 付費投放做冷啟動導流變現。**

⇒ **產出物 = 一個獨立部署、可訂閱收費的網站或 App。**
內容(短影音)在這條線裡**只是導流手段,不是產出物** —— 這一點是它和 YT 線最根本的差別。

## 二、🔴 它跟現有七條線都不重疊(所以是開新線,不是延伸)

| | 核心資產 | 產出物 | 變現 |
|---|---|---|---|
| YT 內容產線 / 副頻道 | 內容 | 影片 | 廣告分潤 / YPP |
| BRAIN 量化 | 交易策略 | alpha | 平台獎金 |
| 台股 / CS2 套利 | 交易策略 | 訊號 | 價差 |
| 數位商品電商 | 內容 | 檔案商品 | 一次性售出 |
| **本線** | **軟體產品** | **一個可訂閱的 App** | **訂閱 + 付費投放** |

最接近的既有物是 `fitness/`(GymLog,PWA,已上 `carsonchou.github.io`)——
但那是**單一免費工具**,沒有訂閱、沒有付費導流、沒有選題方法論。可以當技術暖身,不是同一條線。

## 三、影片給的完整流程(七步,依序)

1. **選題**:用 **TrustMRR**(看別人 App 賺多少錢反推 idea)、**YC's Request for Startups** 找**已驗證痛點**
2. **補技能**:JS(**FreeCodeCamp** JS crash course)→ **FullStackOpen**(React / Node / React Native)
3. **選型**:web 走 **Next.js + Vercel**;mobile 走 **React Native + Expo Go**(他**只做 iOS 不做 Android**)
4. **接服務**:DB **Supabase** / Auth **Clerk** 或 **Firebase** / 付款 **Stripe** / 快取 **Redis**
5. **開發主力**:**Warp**(AI terminal)+ **Claude Code**(他原話:照抄我的工作流,Claude Code 處理幾乎所有開發)
6. **上線前補安全**:rate limit、RLS、**金鑰不進前端**、重工作非同步跑、上線前 load test
7. **冷啟動找前 1000 用戶**:自拍 UGC 短影音仿爆款 / 付費找 micro-influencer / faceless slideshow
   → 找到有效素材後投 **TikTok / Meta Ads** 滾動加碼($30–50 一支起跳)

## 四、🔴 紅線盤點:第 4、6、7 步**三類全中**

| 紅線 | 這條線在哪裡踩到 | 現況 |
|---|---|---|
| **動錢** | Stripe 收付款;TikTok / Meta Ads 投放($30–50/支起) | ❌ **未授權** |
| **對外發布** | 部署上線的網站 / App;新的社群短影音帳號 | ❌ **未授權** |
| **新 API 金鑰** | Supabase / Clerk / Stripe / Vercel 都要**新開帳號辦金鑰**(本專案完全沒有) | ❌ **未授權** |

⇒ **本線的起始授權範圍 = 第 1、2、3、5 步,加第 4 步的「本機跑得起來」那一半。**
明確的邊界是三句話:

> **不辦新金鑰、不部署對外、不花任何一塊錢。**

碰到那條線就停下來寫成一句話問 Carson,**不要自己往前推**。
(判準:這件事會不會產生一個「外面的人看得到」或「帳單上看得到」的結果?會 → 停。)

## 五、第一份派工(不需要任何授權就能做完)

**目標**:把「要做哪個 App」從一句空話變成一份可以拍板的候選清單。

1. 讀 **TrustMRR** 與 **YC's Request for Startups**,列 **5~8 個候選痛點**,每個附:
   - 已驗證的證據(誰在做、賺多少、資料來源網址)
   - 技術可行性(以 Next.js + Supabase 一個人做,要多久)
   - 🔴 **這個 idea 需不需要碰紅線才驗證得了**(有些點子不花錢就測不了,那類要標出來)
2. 對每個候選回答一句:**「這個東西不上線、不花錢,我怎麼知道它有沒有人要?」**
   答不出來的排後面 —— 那是 memory `distribution-before-quality` 的教訓:
   **ch3 花 10 小時 / $194 做品質修正,而 22 支長片合計 11 次觀看。沒有分發管道時品質回報 = 0。**
3. 順帶查一件本專案自己的事:`fitness/` 的 GymLog 已經上線,**它有沒有任何使用者?**
   如果有,那是這條線唯一一個現成的真實分發樣本;如果沒有,那本身就是一個要先回答的問題。

**回報**:候選清單落檔到 `docs/solo-saas/`,回報只給路徑 + 每個候選一行。

## 六、這條線要守的既有制度(和其他線一樣)

- 開工前讀 `CLAUDE.md` 與 `docs/ops/dispatch.md`;非 trivial 任務照 §2 三件套派工
- **驗證不自驗**(§6):自己寫的東西派 fresh-context agent 驗
- context **≥200K 交棒**,寫交棒檔,**不要 compact**
- 動別線的東西之前先 `git log --oneline -8`(多 session 共用同一個 repo)
- 🔴 **本機記憶體吃緊**(2026-09-09:可用 517MB / 19 個 claude 行程佔 9.5GB)
  ⇒ **不要開平行 subagent**,重活排隊做
