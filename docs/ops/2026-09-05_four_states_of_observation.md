## 三個容易混淆的地方

**① 第 1 種和第 2 種長得一樣,但修法相反。**
兩者的表徵都是「沒有告警」。差別在訊號**產生了沒有**:
- 第 1 種:訊號已經寫進檔案/log,只是沒有人去讀 ⇒ 加讀取者
- 第 2 種:訊號的**產生路徑**被上游擋住 ⇒ 加再多讀取者都讀到空的

判準:**去看那個訊號有沒有被寫出來過一次。** 沒有寫出來過就是第 2 種。

**② 第 3 種會偽裝成第 1 種。**
「我們有在量啊」——量的是自己產生的數字。判準:**那個觀測值有沒有可能來自我們控制之外。**
不可能,就是第 3 種,而它只能從外部取得。

**③ 第 4 種要先確認「那個東西還在不在」。**
⚠️ 督導 2026-09-05 提醒:縮圖重刷這格,**去量 CTR 之前先確認重刷現在還在跑**。
如果根本沒在跑,那格就不是「沒有觀測」,是**不存在的東西** —— 不同的答案,而且更便宜。
**先問「它還在嗎」再問「它值多少」。**

## 一個推論:「修掉一條路徑」不等於「修掉那個歧義」

同一個函式可以有**多條**路徑產生同一個空值。基建線 `3cebe4bb` 修的是
`seed_topic_bank` 的第 2 條(例外被吞),而現在真正在發生的是第 1 條(`:431` 早退),
**它仍然靜默**。同理今早我修 `stock_checkup_daily` 的「LLM 全滅被 catch 成 return 0」,
只處理了例外那條;`comment_dept:606` 是同一族的早退型,而我當時沒去搜。

⇒ 盤點 `return 0` 時要**逐路徑**數,不是逐函式數。
掃描器(`scripts/scan_ambiguous_zero.py`)是逐函式比對,所以它給的是**下界不是總數**。

⚠️ 修法**不是**「不准 return 0」。`telegram_command:91` 的「未設 TOKEN → return 0」是**對的**
(真的沒事做);錯的是 `:98` 的「getUpdates 失敗 → return 0」。
**同一個函式裡一條是「沒事」一條是「壞了」而回同一個值** —— 判準是**失敗路徑要回非零**。
不要為了清單歸零而改對的東西。
