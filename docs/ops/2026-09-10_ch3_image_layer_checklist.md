# ch3 六支 —— 影像層檢查清單(渲染後的獨立驗證用)

> 寫於 2026-09-10 01:4x,**渲染之前**。給渲完之後那一次獨立驗證直接用。
> 🔴 **由基建線(監督方)寫,不由 wB:p1(執行方)寫** —— 讓執行者定義自己會被查什麼,
> 是「驗證不自驗」的反面。若 wB:p1 另外寫了一份,那份當**獨立第二意見**比對用,不取代本份。

## 0. 為什麼需要這一份:三輪驗證一次都沒碰過影像

R1~R3 驗的全是**稿、事實、判準、發布路徑、量測**。6 支至今未渲染。
而影像層的歷史事故清單是三輪裡最長的。

⇒ **渲染 + 影像層驗證是一道新閘門,不是最後一哩。**
⚠️ 不要把「三輪收斂」讀成快好了 —— 收斂的是**嚴重度**不是**類型**
(memory `verification-that-cannot-fail`)。

## 🔴 0.1 這份清單的核心:**有兩條查的是「關係」不是「個體」**

第 1 條(版面重疊)和第 3 條(揭露時序偏移)有同一個形狀:
**兩個東西單獨看都完全合法,錯的是它們之間的關係。**

⇒ 逐元素檢查、逐軌檢查對這一類是**結構性盲的**,而且**它們會全綠**。
⇒ 每條檢查都必須明寫「**這條檢查的是關係還是個體**」,
否則下一個實作的人會很自然地寫成逐元素版,然後全綠 —— **那正是事故當初的樣子。**

## 1. 版面重疊(關係)

**歷史事故**:逐元素驗四個邊全綠,而**兩欄實際相撞 22×10 畫素**。

| | |
|---|---|
| 查什麼 | 所有已渲染元素的 bounding box **兩兩之間**的交集面積 |
| **不可以**只查 | 每個元素有沒有出畫面邊界(那是**個體**檢查,對重疊恆為綠) |
| 錯了會怎麼發現 | **不會自己發現。** 觀眾看到兩段文字疊在一起,而所有閘門全綠 |
| 陽性對照 | **用那支真的相撞過的片**(22×10 那次)重跑,檢查必須叫 |
| 陰性對照 | 一支版面正常的既有片,必須安靜 |
| ⚠️ 邊界情況 | 允許的重疊(陰影、外框、刻意疊放)要**明列白名單**,而白名單本身要被檢查是否過期 |

## 2. 黑底黑字

| | |
|---|---|
| 查什麼 | 每個文字元素與其**實際背後畫素**的對比度(不是與「設定的背景色」比) |
| **不可以**只查 | 設定檔裡的前景色 ≠ 背景色(漸層、圖片、疊層會讓設定值失真) |
| 錯了會怎麼發現 | 抽幀時肉眼可見 —— **但只有抽到那一幀才看得到**,所以要逐卡抽不是抽開頭 |
| 陽性對照 | 用發生過黑底黑字的那支片 |
| ⚠️ | 對比度門檻要寫下數值與來源,不要用「看起來還行」 |

## 3. 揭露時序偏移(關係)

**歷史事故**:已上線的片**畫面顯示一個數字、旁白同一刻正唸另一個**,**六支中招**。

| | |
|---|---|
| 查什麼 | **同一時間戳**上,畫面上的數字 vs 旁白稿該時間點的數字 |
| **不可以**分開查 | 「畫面的數字都有來源」+「旁白的數字都有來源」**兩邊都綠,而它們對不上** |
| 錯了會怎麼發現 | 觀眾聽到 minus 0.05 同時看到 0.28。**內部指標看不到**(memory `yt-internal-metrics-blind-to-viewer`) |
| 陽性對照 | 那六支中招的片,任一支 |
| ⚠️ | 這條需要旁白的**時間軸**(字幕/TTS 時間戳),不是只有稿子文字 |

## 4. `focus_techniques` 的無數值列(這一批新開的路徑)

**已知**:有一列 `es = None` / `es_kind = None`(Ariga & Lleras),
守衛讓它印文字不印數字 —— **那是對的,比硬湊一個數字誠實**。

| | |
|---|---|
| 查什麼 | 「三列只有兩個數字」的版面 —— **這個版面沒有人看過** |
| 為什麼危險 | 欄寬是**從有值的列倒推**的(`make_reel.py:344` `vals = [...] or ["x"]`) ⇒ 少一個值可能讓欄寬計算走進沒跑過的分支 |
| 錯了會怎麼發現 | 抽幀。**這一格必須逐幀看,不能靠自動檢查** —— 因為「版面難看」沒有斷言 |
| ⚠️ | 這是**新開的分支 = 沒有任何歷史證據的分支**,它的正確性只被讀過、沒被跑過 |

## 5. 片長貼上界

**已知**:`focus_techniques` **46 秒**、`how_to_remember_what_you_read` **47 秒**,硬帶 **35~50**。

| | |
|---|---|
| 查什麼 | 渲染**後**的實際長度(不是 `--script-only` 的估算) |
| 錯了會怎麼發現 | `make_reel.py` 會印 ⛔ 並回非零 ⇒ **這條有訊號**,是清單裡唯一會自己叫的 |
| 🔴 處置 | 超標就**改稿重渲**。**不准為了不重渲而放寬硬帶。** |
| ⚠️ | 兩支都貼上界 ⇒ 預期會發生,不是意外。**事先決定好「改哪一句」比事後決定誠實** |

## 6. 這份清單自己的限制(和清單一起讀)

1. **這五條是歷史事故清單,不是完整的失效空間。** 影像層第一次被驗,
   **沒被列出來的失效模式沒有被排除** —— 只是還沒發生過。
2. **第 4 條沒有自動斷言**(「版面難看」寫不成判準)⇒ 它靠人眼,而人眼會累。
   排在抽幀流程的**前面**,不要排在最後。
3. 🔴 **通過這份清單 ≠ 影像沒問題。** 它的正確讀法是
   「**這五個已知的坑沒有再踩一次**」。
