# 2026-09-03:重生不是重試,是重擲同一顆骰子

> 寫這份檔的理由:有一個**沒被驗過的獨立性假設**,支撐了這條線上
> 「加一道閘門的成本很低」這個通用判斷。它被實測推翻了 10~270 倍,
> 而 08-29 整天零成稿是它第一次以事故形式出現。
> 這件事會改變之後每一次「要不要再加一道閘門」的決定,所以它必須在程式碼之外留檔。

## 一、那個推論在哪,支撐過什麼

`memory/yt-period-swap-integrity.md:116-117`:

> 「新稿閘門殘餘率 23.1% ⇒ fail-closed 約 1.2%」

那是 **0.231³**。而立方**只在三稿彼此獨立時成立**。

它支撐的不只是期間偷換那一道閘門。它是「**再加一道閘門的產線成本很低**」的通用理由:
每加一道殘餘率 r 的閘門,大家心裡算的是 r³(≈ 千分之一),
而 `_long_bad` / `_uncontroversial_bad` 裡每一道 fail-closed 閘門
(長度、資訊密度、prompt 洩漏、分鏡指示、標題矛盾、段數)都是靠同一個心智模型加進來的。

## 三、根因:重生迴圈原本沒有回饋

`call_claude(kind, avoid, topic_override)` 的簽章**接不住失敗原因**。
失敗原因算出來了(`_hist.append(...)`)、寫進 log 了,然後**丟掉**;
而 `_ex = existing_titles()` 是迴圈外算一次的去重表,三次呼叫從不更新。

**所以三次重生是三個位元組完全相同的呼叫,只差 LLM 取樣隨機性。**
那不是「重生沒收斂」,是**沒有迴圈**。

已於 `6123fc37` 加上 `retry_reason` / `retry_n`(六條迴圈中的兩條,見第五節)。

## 四、🔴 通則:往 fail-closed 閘門加東西之前,成本要用「接近 r」估

不是 r^n。

- n 次重生把殘餘率壓到 r^n,**前提是每次重生是獨立重抽**。
- 這條線的重生**不是**獨立重抽:模型看到的輸入完全相同,失敗模式因此高度自相關。
- 實測條件失敗率**不隨重生次數下降**——第 2 次失敗的機率和第 1 次差不多。

所以估算新閘門成本時:

```
❌ 成本 ≈ r³ × 產量          (千分之一,「幾乎免費」)
✅ 成本 ≈ r  × 產量          (十分之一到四分之一,會實際吃掉良率)
```

**這個差距是 10~270 倍,而它不會在單日良率上顯示出來**(良率每天在 0~96% 之間擺),
只會在某一天以「整天零成稿」的形式出現。08-29 就是那一天。

⚠️ 附帶結論:**在重生變成真的有回饋之前,加閘門的成本估計一律用 r。**
即使回饋上線了,也要先用 `tests/regen_feedback/selfloop.py` 量到自環率真的下降,
才能把估計往 r^n 的方向調 —— **不要拿良率上升當證據**,那個指標的雜訊蓋過訊號。

**本輪只加觀測,不加回饋。** 理由:①②⑤ 原本**連失敗原因都沒算、一行 log 都不寫**,
447 行日誌裡完全看不到它們 —— 而它們在燒 LLM 呼叫、燒題庫,
**沒有任何人知道燒了多少**。在不知道多久觸發一次之前替它們加回饋,
是在改一個看不見的東西。跑過一輪之後再決定:
**如果實測幾乎不觸發,那就不必改 —— 少改一個不必改的東西,比多改一個更安全。**

嚴重性的實話:個股體檢佔產出 93%,而它 `_is_ck=True` 跳過 ①、`_is_tw_stock=True` 跳過 ⑤,
所以對主力產品而言,未餵回饋的那四條多半不觸發。**這也正是它們一直沒被發現的原因。**
