## 二、誠信閘門:最終判準與為什麼是這個數

### 背景:舊守門已經失效

`fact_source_guard` 用**全域**事實池(38,231 個數字)比對。實測 pct 子池在 0~200 區間有
20,704 個值、相鄰間距中位 **0.0032**,而嚴容差是 `max(0.25, 值×0.5%)` ≥ 0.25 =
間距的 78 倍 → **池子實質連續,任何百分比都找得到鄰居**。
隨手編的 1234.5% / 777.7% / 88.8% / 42.195% 全部判「有憑據」;隨機 400 個百分比通過率 **100%**。

它不是壞掉,是**慢慢失效**:2026-07 建立時事實庫只有 5 組,擋得住;現在 504 檔 × 13 組
把池子填滿。→ memory `yt-fact-guard-pool-saturation`

### 新閘門 `_long_corrupt_number`(produce_batch.py)

**判準**:同一句話裡至少 2 個百分比,其中 **≥2 個對得上該股自己的事實**、而 **≥1 個對不上**。

**為什麼是「≥2 對得上」而不是 1**:一個對得上可能是巧合(池子密),兩個對得上代表
「這句話正在抄事實」,那麼第三個對不上就是抄壞了,不是修辭。實例:

```
信昌電6173  旁白 總報酬 794.7% / 年化 29.2% / 回撤 74%
            事實 總報酬 1194.7% / 年化 29.2% / 回撤 -74.0%
```

**兩道放行(偽陽性全落在這兩類,是抽驗調出來的不是設計出來的)**:
1. 假設/舉例語境整句跳過 — `假設 舉例 例如 比方 以為 想像 打個比方 如果你 換算 相當於 意思是 也就是說`
2. 「超過/不到 + 概數」— 池裡有值在正確那一側且差距 ≤ `max(15, v×0.25)` 就算溯源到

**調校過程(命中數)**:12 → (加放行①) 3 → (加放行②) 3,但成員換了一支。

## 七、量測方法的坑(踩過才寫的)

- **不能比對阿拉伯數字**:旁白一律中文唸法。比主題關鍵詞,或用 `_cn_num` 轉。
- **主題關鍵詞也會漏報**:`annual_extremes` 旁白寫「在二零零八年…」不寫「最慘一年」。
- **`ya.video_stats()` 被截斷 200 支**(Analytics 對 `dimensions=video&sort=-views` 硬上限,
  `limit` 調到 1200 仍只回 200)。全量要用 `filters=video==` 批次(≤200/批)。
  **我用截斷樣本算過一次門檻,而 r(觀看數,留存)=-0.406 → 樣本偏向「看起來像輸家」那端。**
- **片齡是致命混淆變數**:按發布量分組看「每支觀看」會得到「9-12 支/日崩塌到 3 次觀看」,
  控制片齡後發現那 31 支**全是 61 天以上的舊時代片**,同齡的 1-4 支/日也只有 4 次。
- **寫入後立刻回讀是快取**:刪留言後回讀仍顯示 2 則,等 25 秒才變 1 則。
- **fail-open 的防護壞掉時沒有聲音**:`ch3_lab` 路徑寫錯 → 檔案不存在 → 回 0 → 防護等於沒裝
  而且不報錯。**驗證不能只驗「不炸」,要驗真值**(自檢「應該回 3 卻回 0」才抓到)。

## 九、發布量 vs 每支觀看:分解結果(2026-09-01 晚,Carson 指定)

### 問題

`4.3 小時/支 = 15,480 秒 ÷ 122 秒/次 ≈ 127 次觀看/支`(與 memory 實測中位 121 吻合)。
所以觀看小時由**觀看次數**主導,不由每次秒數主導。而 memory `yt-search-entry-decides-views`
有一張表暗示觀看次數被發布量壓著(1-8支→118、9-20支→73,n=14),
若成立則「8→11 支」讓每日總觀看**少 15%**,今天一整天的方向就是反的。

### 做法

`videos.list part=snippet,statistics` 全樣本(1,031 支 / 21 units),**不用** Analytics 的
`dimensions=video&sort=-views`(Top-200 截斷,本專案已在上面錯過兩次)。
只取長片、發布滿 4 天(成熟)= **204 支**。

### 結果:未控制片齡時看起來像崩塌

```
當天長片發布量    片數   觀看中位
1-2 支            34      172
3-5 支           100      154
6-8 支            33       81
9+ 支             37        2    ← 崩塌
```

### 控制片齡後:崩塌是時代差異,不是產量效應

```
片齡          1-2支        3-5支        6-8支       9+支
4~20天    356(n=11)   148(n=30)   185(n=6)      n=0
21~45天   199(n=11)   220(n=50)   113(n=21)     n=0
46~70天    19(n=12)    26(n=20)     4(n=6)   2(n=37)
```

**9+ 那格 37 支全部發布於 2026-06-23~06-30**(片齡 63~70 天),是頻道起飛前的舊時代;
同齡層(46~70天)裡 1-2 支的片也只有 19 次觀看。

**沒有單調負斜率。** 21~45天那列 3-5支(220)反而**高於** 1-2支(199);
4~20天那列 6-8支(185)反而高於 3-5支(148)。雜訊大於訊號。

### 目標函數(每日總觀看 = 支數 × 該區間中位)

用 n 最大、最完整的 21~45 天那列:
```
1-2 支/日  →  2 × 199 = 398
3-5 支/日  →  4 × 220 = 880   ← 峰值
6-8 支/日  →  7 × 113 = 791   ← 只低 10%,而 n=21 撐不起這個差距
```
用 4~20 天那列會得到**相反的排序**(6-8支 > 3-5支)。

### 結論

**假設沒被證實,也沒被推翻 —— 現有資料回答不了這個問題。**
根本原因:**新時代從來沒跑過 9+ 支/日**,那一格 100% 是六月的舊片。
11 支/天 2026-09-01 才第一次跑。

→ 唯一能回答的方式是**讓它跑,09-15 量**(今天這 11 支發布滿 14 天)。
在那之前調發布量(往上或往下)都是拿感覺蓋掉沒有的資料。

⚠️ 同一個「片齡混淆」陷阱**當天踩了兩次**:下午看「每支觀看 3 次」差點反轉發布量決策,
晚上這次又看到「9+ 支崩到 2 次」。**兩次都是同一批六月的舊片。**
按發布量分組看表現時,片齡控制是必要條件不是加分項。
