## 五、方法論(唯一會隨 context 消失的)

1. **三輪獨立驗證,每輪都推翻我一件事,而三件的形狀相同:我把話講得比證據滿。**
   ①註解宣稱「兩層都不經過 `_load_existing()` 回傳值」——把 `min_ratio` 設 0 一跑就破;
   ②「不可以動到別的代號」只數筆數,而覆寫不改變筆數;
   ③`lost_codes` 那格根本不可能觸發。
   ⇒ **承重的註解錯了比程式錯危險一級**,因為下一個人會照它下判斷而不會去跑它。
   ⇒ 寫下任何「這道閘門保證 X」之前,先問:**有沒有一整類輸入會讓它恆不叫?**

2. **`grep` 找不到不等於不存在 —— 要用「它可能叫什麼」而不是「我會怎麼命名」去搜。**
   我搜 `atomic_write|os.replace|def atomic` 判定「專案沒有原子寫工具」,
   而它叫 `save_json_atomic`,20+ 支腳本在用。差點重複造輪子。
   ⇒ 宣告「不存在」之前,改用**行為**去搜(這裡應該搜 `.tmp`、`replace(`、或直接看 `studio_common`)。
   同族:memory `read-the-sibling-tool-first`。

3. **驗證員說「沒有第二條路」也要驗。** 它第二輪答「全部寫入都經過 `merge_and_write`」,
   而 `checkup_industry_rank.py` 就在排程上繞過去。第三輪換謂詞(找**寫到那個路徑**的所有地方,
   不是找 `merge_and_write`)才掃出來。⇒ **否定性結論要問「你用什麼謂詞掃的」。**
   同族:memory `static-reading-vs-runtime-behaviour`「錯的否定比錯的肯定危險一級」。

4. **修法可以引入舊碼沒有的失敗模式,而那不會出現在「有沒有修好」的檢查裡。**
   `os.replace` 在 Windows 上目標被開著讀就 `PermissionError`,舊碼 `write_text` 寫得進去。
   這個檔有十幾個讀取端。⇒ **每個修法都要問一次:舊碼在哪些情境下能過而新碼過不了?**

5. **`heredoc-backslash-escaping-trap` 今天連踩兩次,第八次就發生在我寫「第七次」那段教訓的當下**
   (連記憶檔的 YAML frontmatter 都被吃斷)。⇒ **知道這個坑不構成免疫。**
   規矩改成沒有例外的兩條:①文字裡出現反斜線就一律用 Edit/Write 工具,連「在文件裡提到它」也算;
   ②heredoc 寫完一律回讀 —— 這次 `python` 那頭回報 `ok`,**工具說成功不代表內容是對的**。

6. **改產線檔要驗「行為零改變」而不是「我只改了註解」**:`snapshot_studio.py` 那次用
   AST 逐字比對 HEAD vs 工作區,**並帶陽性對照**(插一行真程式碼,確認比對器會叫)。
   腳本形狀留在 scratchpad `astdiff.py`。
