## 根因(兩個獨立機制,都在 `scripts/produce_batch.py`)

### ① 補強機制存在但會靜默 fail-open(結構性,可重現、非隨機)
- `_checkup_summary_line()`(produce_batch.py:1719-1793,2026-09-05 上線):組裝「一句話收束」的
  確定性函式,**不呼叫 LLM**。判準寫死「缺任一支柱就回空字串」(docstring line 1736-1738,實作 line
  1757-1758 `if not (lh and val): return ""`)。四支柱來自 `STOCK_CHECKUP_FACTS`
  的 `checkup_long_horizon` / `checkup_valuation_position` / `checkup_underwater` / `checkup_industry_rank`。
- `_checkup_finalize()`(produce_batch.py:1829-1898)在 `_checkup_has_real_summary(v)` 為 False 時
  呼叫上面函式插入(line 1857-1860),但**没有為「_checkup_summary_line 回空字串」這個分支印任何警告**——
  呼叫端看不出是「已經有收束句」還是「資料不足所以放棄」。
- **實測證實**:萬潤6187 在 `STUDIO/stock_checkup_facts.json` 裡
  `checkup_valuation_position` 和 `checkup_industry_rank` 兩支柱都是 MISSING → 函式必定回空字串 →
  `_checkup_finalize` 什麼都沒插入 → 該片只剩 LLM 自己寫的空話 CTA。萬潤6187 產出於 09-09,晚於
  09-05 上線時間,證明**機制在線但對這支股票沒生效,不是機制不存在**。
- 這個根因是**結構性、可重現**的:同一支股票只要事實庫缺對應四支柱之一,每次重生都會是同樣結果,
  不是 LLM 隨機漏寫。

### ② 假陽性判準漏掉零數字填充句(結構性,今天(09-15)才修,尚未回溯舊片)
- `_checkup_has_real_summary()`(produce_batch.py:1811-1826)原本(09-05版)只做關鍵字比對
  (`CHECKUP_SUMMARY_MARKERS`,line 1362:「一句話收束/總結/整體而言/綜合來看/結論是」)。
  LLM 只要寫出「總結而言,投資沒有捷徑,謹慎評估比什麼都重要」這種零數字填充句就會被誤判成「已收束」,
  補強被跳過。
- **今天(2026-09-15)的 commit 內註解(produce_batch.py:1797-1808)本身就是這個缺陷的修法**:改成
  「命中關鍵字的那句(+下一句)裡必須真的出現百分位/回撤/套牢/年化/總報酬/報酬率或數字+% 才算真收束」。
  校準樣本明確點名「中探針6217」「新唐4919」兩支就是這類假陽性。
- **中探針6217 本次仍被判為純空話**,因為它是 09-14 產出的**舊片**,這個修法只影響**之後**新產出的片,
  不會回溯修正已發布的內容。
- 這是模板判準本身的缺陷(關鍵字比對 vs 語意內容),**不是 LLM 隨機漏寫**——同一套判準邏輯對所有片
  一視同仁地誤放行,是系統性的。

### 補充:基礎 prompt 本身也沒有要求「數字收束句」
`generate_script.py:243`(通用腳本 prompt,個股體檢系列共用其 outro 段落)只寫「結尾(OUTRO):收束主題、
呼應開頭,留下記憶點」,沒有要求「用具體數字給出結論」。個股體檢系列真正的數字收束句(9/20 那批)
**全部來自 `_checkup_summary_line` 的確定性拼接,不是這段 prompt 引導 LLM 寫出來的**——這段 prompt
本身無法解釋任何一支「有數字收束」的樣本。

## 模板性 or 隨機性?
**兩個根因都是模板性/結構性,不是 LLM 隨機漏寫**:
- 根因①(fail-open)由「該股票事實庫是否齊全四支柱」決定,同一股票每次重生結果相同,可用事實庫缺口預測。
- 根因②(假陽性判準)由「LLM 是否寫出關鍵字但無數字的填充句」決定是否觸發補強,規則邏輯本身有漏洞,
  對所有符合該模式的片一視同仁地漏放,不是隨機事件。
- 唯一帶有「隨機」性質的部分,是 LLM 自己要不要寫填充句(觸發根因②與否),但漏洞本身(判準太寬鬆)是
  結構性的,已被今天的 commit 認定並修正(只是未回溯)。
