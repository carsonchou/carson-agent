## 4. 🔴 陰性對照:偵測器分得出「沒有那句話」和「我沒讀到」嗎?

這一步是督導指定的硬前置,結果:

| 樣本 | 來源 | 結果 |
|---|---|---|
| `y_pggXEwZJo`「穩定幣買美股能跑網格?Bitget Stock+」 | 已發布、**不在 84 裡** | 讀到 ✅,判 **MARK=無**(desc 384 字) |
| `mxV56GTL-oI`「AI寫的量化系統90%虧錢」 | 已發布、不在 84 裡 | 讀到 ✅,判 **MARK=無**(desc 538 字) |
| `YPQpGOlsJMs`「勝率87%卻虧光?」 | 已發布、不在 84 裡 | 讀到 ✅,判 **MARK=無**(desc 457 字) |
| `ZZZZfake000` | **蓄意造假、不存在的 id** | **讀不到 ✅**,歸到「讀不到」那一格,**沒有被誤判成「無 MARK」** |

⇒ 兩個方向都驗過了:
①「確定沒有那句話」的真影片會被判成 **無**,不是靜默漏掉;
②「根本讀不到」的 id 會被判成 **讀不到**,不會混進「無」。

這一格是必要的,因為 `videos.list` 對於讀不到的 id **不報錯,只是不回傳那一筆** ——
如果只數 `items` 而不比對「送出的 id」vs「回來的 id」,一支讀不到的片會長得跟
「有讀到、但沒有那句話」一模一樣。實測第二批送 38 支只回 37 支,差的那支正是造假 id。
(memory `filter-accepted-is-not-filter-applied` / `static-reading-vs-runtime-behaviour`)
