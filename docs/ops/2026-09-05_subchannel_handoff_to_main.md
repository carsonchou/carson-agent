### 🔴 這條是給下一個決策用的,不是知識

總督導可能會轉一個副頻道的發現過來要求證偽:
**「直式 37 支 345 觀看(9.3/支) vs 橫式 22 支 16 觀看(0.7/支),13 倍,同題材同產線同閘門」**。
那個效應是真的(同頻道同閘門的乾淨對照),**但它的幣別是觀看**。
照上表匯率,13 倍原樣兌現成發布配比,換到的是 **3.9% 的分鐘**。

⇒ **證偽或採用那個效應時,應變數用 `estimatedMinutesWatched`,不要用 `views`。**
用觀看當應變數會讓一個真實的效應做出反向的決定。
(這與 memory `yt-shorts-not-converting-2026-08`、`yt-format-pivot-longform-2026-07` 同向:
YPP 4000 小時算的是分鐘,不是觀看。)

# 🔴 我(main ch.)加的一件:我們每天付錢拿這一欄然後扔掉

`youtube_channel/scripts/beachhead_tracker.py:46-48` 的查詢**已經**是
`metrics="views,estimatedMinutesWatched"`,但落盤時:

```python
total = sum(x[1] for x in rows)                       # x[1] = views
detail = {x[0]: x[1] for x in rows if x[0] != "SUBSCRIBER"}
```

**`estimatedMinutesWatched` 是 `x[2]`,從頭到尾沒有被讀取。**
`STUDIO/` 底下的 beachhead 歷史檔因此只有觀看,沒有分鐘 ⇒
上面那個匯率**現在無法用自家落盤資料獨立驗證**,雖然那份資料每天都被抓下來過。

⇒ **已修**(09-05,fresh-context 獨立驗證四輪,`dispatch.md` 第 6 節)。
第一筆帶 `minutes_*` 的紀錄會是 **2026-09-06 06:35**(寫的是 09-02 的資料)。

### 驗證打掉的東西(全部是我寫的,列出來因為形狀會重複)

| # | 我寫的 | 實際 |
|---|---|---|
| D1 | 加總 `x[2]` | 第 3 欄回 null/字串時 `sum()` 炸掉整支,而例外在 try/except **之外** ⇒ **把本檔宣稱的 fail-open 收窄成 fail-closed**,連觀看數那一半也沒了 |
| 3-A | 守衛只守 `x[2]` | `_hdr` 同時是 `x[1]=views` 的唯一憑據。欄位真對調時 `total` 變成分鐘、被當觀看落盤,而告警只講分鐘 —— **把讀者導離出事的那一半**,且冪等鎖死 |
| 3-B | `else h`(修 AttributeError) | 讓守衛**接受了一個從沒觀測過的形狀**(headers 裝字串時竟然比對成功)。修崩潰時順手放寬了合約 |
| 3-C | 告警放在冪等**之前** | 補跑每次多一條孤兒 ⚠️,洗版=沒有警報 |
| — | 「YPP 算的是分鐘」 | 註解本身是陷阱:`minutes_total` 含 SHORTS 分鐘,**不等於 YPP 可計時數**。資料是對的,錯的是語意,合成測試測不到 |

🔴 3-A/3-B 是我**讀過 D1 之後**、在自己剛寫的十行裡踩的同一種病。
判準:**寫守衛時問「這個訊號還蘊含了什麼」** —— 3-A 的 `_hdr` 不合,蘊含的不只是分鐘可疑。

### 兩個設計決定(理由值得留)

**① headers 對不上時,`views` 那一半寫不寫**:分兩種,不一刀切。
`_hdr[1]` 明講不是 `views` = **正面反證** → 整支放棄不落盤;
`_hdr` 缺失或太短 = **拿不到憑據但也沒有反證** → 照寫觀看、只省略分鐘。
(驗證員第一版也是一刀切,跑 G1 才看到自己把 fail-open 打掉了。)

**② 跳閘那天分鐘四欄「整組省略」而不是填 0**:
「有鍵值為 0」和「真的看了 0 分鐘」在 jsonl 裡無法區分,**缺鍵可以**;
且與 09-06 之前那 18 列同形,讀取端一套 `.get()` 涵蓋兩者。
⚠️ 驗證員原本想用「洞看得見」支持「斷比錯好」,**實算後自己推翻**:
那個檔 24 天裡已經有 6 個洞(25%),多一個看不出來。
結論仍是「斷」,但理由改成:**洞不會被當成資料用,錯的那列會參與趨勢且被冪等鎖死。**
