### 這件的教訓有兩層,第二層比第一層重要

**第一層(執行端)**:我 17:5x 宣告「旗艦片不會佔掉 checkup 的名額」——
那句話**對了一半**:它沒佔到選片名額,但它佔到了**配額**。
**只查了一個維度就把「A 沒事」講成「沒事」。**

**第二層(指令端,督導自己指出)**:那次發布是督導批的,而他交代的是
「注意別讓它**佔掉名額**」——**他問的是名額,而真正會被吃掉的是配額。**
⇒ **上游問錯問題的話,下游查得再仔細也答不到點上。**

🔴 **收到「確認 X 不會影響 Y」這種指令時,先問「還有哪些管道會讓 X 影響 Y」,
不要只答被問到的那一條。** 被指定的那個維度是提示,不是清單。

## 預期支數的算法(更正版,以後照這個寫)

```
預期上架數 = min(通過閘門的候選數, --max, floor(當時 remaining / 1600))
             且扣掉當天其他已知支出(縮圖 50/支、字幕、播放清單、留言…實測每支總開銷 ≈ 2,200)
隔離數    另計 —— 它不在 --max 的計數裡,是額外的
```

🔴 **加一條(今天付了學費才有的)**:
**任何排程外的手動發布,都要在當下就把 1,600 units 從當天剩餘配額裡扣掉並記一筆。**
今天的順序是「先發旗艦 → 18:30 照原計畫跑 → 事後才發現少一支」。
**那筆扣帳如果當下就記了,18:30 的預期值會自動變成 9,就不會有一個對不上的數字要查一小時。**
