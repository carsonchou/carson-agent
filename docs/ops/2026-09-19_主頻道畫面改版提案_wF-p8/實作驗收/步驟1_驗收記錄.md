# 步驟 1(P0 估值圖 x 軸被離群值撐爆)驗收記錄

改動檔案:`youtube_channel/scripts/concept_visuals.py` 的 `_valuation`(單一函式)。

## 缺陷與修法

舊版 `lo=min(p25,cur)*0.85 / hi=max(p75,cur)*1.12`。`cur`(latest_per)是離群值時
(EPS 趨近 0 或虧損的個股,本益比會噴到幾百上千倍),整條 x 軸被 `cur` 一個點撐開,
這張圖真正要傳達的 P25~P75 箱型被壓成一條髮絲。

- 3714 實測:箱型只佔畫布寬 **1.65%**,三個刻度標籤疊成「P2位數1 20」完全不可讀。
- 這張圖在成片裡停留 **155 秒**(第 5 段,`valuation`)。
- 母體(`STUDIO/stock_checkup_facts.json` 全部有估值資料的個股):**693 檔中 142 檔(20.5%)**
  箱型 < 30% 畫布。不是 3714 個案。

修法:x 軸視窗**只由箱型區間決定**(`pad = (p75-p25)*0.35`),`cur` 落在窗外就釘在畫布
邊緣 6%/94% 處,標記改三角箭頭,文字明寫「(超出區間)」,並依位置換 `ha` 避免被畫布切掉。

**為什麼不用對數軸**:這張圖 `ax.set_xticks([])`,本來就沒有 x 刻度;對數軸的壓縮比例在
畫面上無從辨識 = 視覺上把 992 倍畫得像 30 倍,那是誤導。受眾是新手(見 `_maybe_log_y` 註解
與 memory `yt-beginner-repositioning`),對數軸讀不出來。釘邊 + 把真實數值原樣寫出來,
是唯一不犧牲誠信的選項。

**為什麼 pad 用箱寬不用中位數尺度**:`p50*0.15` 當 pad 會讓區間很窄的個股(如中華電 2412,
P25~P75 只差 4 倍)反過來被自己的中位數尺度稀釋到 35% 畫布。

### 🔴 前兩次的基準是無效的,記在這裡不刪

第一輪量到 BEFORE 319.1s / AFTER 378.5s,看起來是 +18.6% 退步。幅度跟改動內容完全對不上
(`_valuation` 只多了幾行算術,全片第 5 段 × 8 bucket = 8 次呼叫),所以先查儀器而不是先信數字。

根因:`concept_visuals.py` 用 `Path(__file__).resolve().parent.parent / "STUDIO"` 找真價格 CSV
與體檢事實庫。BEFORE 用的是放在 scratchpad 的**凍結副本**,那個相對路徑指到不存在的目錄 →
`_FACTS_CACHE` 不存在、事實庫 0 筆 → **所有真資料 drawer 一律回 None** → 整支片一張概念圖都沒畫。
探針實測:`存在? False / facts 條數: 0 / valuation 出圖? False`。

也就是說第一輪比的是「沒畫圖的渲染」對「有畫圖的渲染」
(memory `wrong-baseline-measures-the-design`)。BEFORE #1 319.1s、BEFORE #2 336.2s 兩次都無效,
不是「舊版比較快」。

修法:harness 在 import 之後把兩個資料來源指回正式機絕對路徑,並加一道**探針斷言**——
真資料估值圖畫不出來就直接中止,不准再量到退化版渲染。只動資料位置,不動任何繪圖邏輯。

### 有效對照(兩邊都確認有畫概念圖)

| 版本 | concept_visuals 來源 | rc | 耗時 | 概念圖 |
|------|----------------------|----|------|--------|
| BEFORE #3 | HEAD 的凍結副本 + 資料來源指回正式機 | 0 | **317.6s** | 有(數字爆現 2 個 overlay) |

**結論:AFTER 比 BEFORE 快 13.2s(-4.2%),沒有退步。** 兩次都 rc=0、不崩、不逾時,
輸出總長都是 636.2s、切片 240 段、字幕 233 句。

-4.2% 不宣稱是「修法讓它變快」——同一份舊程式兩次量到 319.1s / 336.2s,機器本身的變異就有 5%,
這個差值落在變異裡。能宣稱的只有:**改動沒有帶來可量測的成本**。
