## 為什麼是暗金,不是換個顏色就好

改版前那張圖的觀感問題不只是「綠色太亮」,是三件事疊在一起:

1. **飽和亮綠 (88,220,140) 配純黑底 (10,14,26)**,是整張畫面亮度最高的東西。
   Carson 反覆嫌成品「太亮/刺眼」(memory `carson-prefers-dark-ui`)。
2. **1px 髮絲線**在 1920x1080 壓到手機上幾乎看不見,只好再調亮 → 更刺眼,惡性循環。
3. 🔴 **根因其實不在顏色**:`render_concept_chart` 一開場 `set_yticks([])`,
   於是它下一行的 `ax.grid(axis="y", ...)` **一條格線都畫不出來**(沒有刻度就沒有格線)。
   「一條線浮在全黑畫布上」的空蕩感來自這裡。只調色不補刻度,改完還是空的。

做法:`GOLD (0.82,0.64,0.27)` / `GOLD_DARK (0.30,0.22,0.09)` 兩端漸層,亮度與飽和度
各退一階;glow 只鋪兩層低 alpha,不做霓虹;並把 y 刻度與細格線加回真資料圖。

### 語意色一律不動

RED/GREEN 在這條產線上**帶判讀意義**,不是裝飾:

| 位置 | 顏色的意思 | 處置 |
|------|------------|------|
| `_valuation` 目前值標記 | 紅=現在貴 / 綠=現在便宜 | **維持**,這是整張圖唯一的判讀訊息 |
| `_crosssec` 腰斬線右側長條 | 紅=曾經腰斬 | **維持** |
| `_crosssec` 腰斬線左側長條 | 無語意,只是「其他」 | 改金色 |
| `_candles` K 棒紅綠 | 漲/跌 | **維持** |

把語意色染成金色等於把資訊抹掉,那不是重皮,是改壞。

## 覆蓋率:第一版只改到 8 個真資料 drawer 中的 5 個

這是這一步最容易假完成的地方——改完看起來變好看了,但有三張圖根本沒被碰到,
而它們一樣會出現在成片裡。逐一清點(不是憑印象,是掃函式主體):

| drawer | 真資料? | 重皮後具備 |
|--------|---------|-----------|
| `_drawdown` | 真資料 | glow + y 刻度 |
| `_history` | 真資料 | glow + y 刻度 |
| `_trend` | 真資料 | glow + y 刻度 |
| `_dca` | 真資料 | glow + y 刻度 |
| `_fundamentals` | 真資料 | 暗金漸層柱 + y 刻度 |
| `_valuation` | 真資料 | **第二版才補**:箱型暗金漸層 + 中位數 glow |
| `_candles` | 真資料 | **第二版才補**:價格刻度(原本一條價格刻度都沒有) |
| `_crosssec` | 真資料 | **第二版才補**:長條改金 + 「檔」刻度 |
| `_grid` / `_compound` / `_martingale` | rng/機制示意 | **刻意不給數值刻度** |

最後一列是誠信線,不是遺漏:`_martingale` 畫的是 2^n 的確定性示意,`_grid` 是 rng 概念圖。
**替一條示意線加上數值刻度,等於把它背書成「這是量出來的數字」**,那比沒有刻度更糟。

`_valuation` 尤其不該漏——它在成片裡停留 **155 秒**,是停最久的一張,
卻是唯一還留著白色半透明色塊、跟其他圖不同調的。

## 🔴 我自己改出來的缺陷,以及量尺怎麼騙過我

加回 y 刻度之後,**最低的那個刻度撞到年份標籤**:3714 回撤圖 r=0.625 的「40」壓在「2021」上。

`prune="both"` 擋不到——它只砍「剛好等於視窗邊界」的刻度,而 `MaxNLocator` 會把視窗往外
推成整數,最低刻度落在邊界**內側一點點**。

第一版修法(砍掉下緣 10% 的刻度)**量起來沒有效**。沒有猜,直接量:

```
axes bbox : [115.2, 496.8, 1804.8, 928.8]   (軸高 432px)
ylim      : (33.15, 96.85)      → 10% 門檻 = 39.52,刻度 40.0 以 0.48 之差存活
'2021'    : x[ 89.4, 141.0]  y[516.5, 538.5]
'40'      : x[ 88.2, 112.4]  y[529.8, 551.8]      → 交集 23.0 × 8.7 px,真的疊到
```

量出來兩件事之前都想錯了:
- 年份標籤是**畫在軸內**下緣的(y 516.5~538.5),不是畫在軸外下方 → 碰撞帶是軸高 2.7%~11.5%;
- 第一個年份標籤置中在 x=0 那一格,會**往左伸進 y 刻度那一欄**(x 89.4 vs 刻度 88.2~112.4)。

門檻改 **12%**(留約 0.5% 餘裕 ≈ 6px),40 被砍掉,60/80 保留。

### 量尺本身壞掉了兩次,兩次都是「檢查不可能失敗」

**壞法一:量物件圖,不是量算繪結果。** 第一版用 `fig.findobj(Text)` 列舉文字。
Axis 上每個 Tick 都掛著 Text 物件,**視窗外的刻度不會被畫**(`Axis.draw` 只取 view interval 內的),
但那些物件還在、還帶著舊座標。於是量到 94 個「文字出界」,全是對數軸的幽靈刻度(`0.01`/`1,000`)。
症狀很明顯:**正常模式和陽性對照跑出一模一樣的輸出**——門檻改了它卻一個字都沒變,
代表它根本沒在量我改的東西(memory `static-reading-vs-runtime-behaviour`)。
改成掛在 `Text.draw` 上錄實際進到畫面的文字,[B] 立刻從 94 變 0。

**壞法二:母體挑好取的那批。** 第一版「排序後取前 25 檔」,結果 25 檔全是 1101~1409 的
水泥塑化股,**我這次改出來的碰撞現場 3714 根本不在母體裡**。改成跨代號區間等距取樣 +
強制納入已知現場(memory `gate-verification-population`)。

**壞法三:只跑 reveal=1.0。** 漸進揭露每個 bucket 的資料窗口不同 → ylim 不同 → 刻度落點不同。
「40 壓 2021」**只在 r=0.625 出現**,同一檔同一張圖 r=1.0 是乾淨的。成片每個 bucket 都會播,
母體就得含 bucket。加上 3 個揭露階段後,量尺才第一次看見這個缺陷。

三次修的都是量尺,不是被量的東西。記在這裡是因為前兩版量尺都會給我一個「全過」。

(紅線:不重渲已上架影片、不發布、不動排程)。

| 版本 | concept_visuals 來源 | rc | 耗時 |
|------|----------------------|----|------|
| BEFORE | 步驟 1 的 AFTER #2(同一份正式碼、同一支 harness) | 0 | **304.4s** |
| AFTER | 暗金重皮後的正式碼 | 0 | **305.9s** |

BEFORE 直接沿用步驟 1 的 AFTER #2:那正是「重皮之前的正式碼」,同機器同 harness,
重跑一次只會多引入一次機器變異。

兩次的產出結構一模一樣(`切片=240段 字幕=233 總長=636.2s`),沒有掉段也沒有多段。

**+1.5s(+0.5%)不構成「變慢」的證據,也不構成「不變」的證據。** 步驟 1 的記錄裡
同一份程式碼量過 319.1s 與 336.2s,機器本身的變異就有 5% —— 1.5s 遠在雜訊之內。
唯一站得住的結論是:**重皮沒有帶來可量測的成本**,不是變快,也不是變慢。
要證到 1.5s 這個量級得重複跑十幾次取分佈,那個精度對這個決定沒有用處。
