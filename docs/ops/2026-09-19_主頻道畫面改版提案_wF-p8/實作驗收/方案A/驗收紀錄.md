# 方案 A(同段內換視角)實作驗收紀錄

日期:2026-09-19 · 執行者:wF:p8 subagent · 目標:主頻道長片 `youtube_channel/scripts/render_ffmpeg.py`

## 1. 改了什麼

`_reveal_base` 原本把一段的 8 個 reveal bucket 全部畫**同一張圖**,只是揭露比例從 35% 長到 100%。
一支 ~620s 的片有 5~7 段 → 全片只有 5~7 張真正不同的圖,單圖停留 ~150 秒。

改法:把每段再切成 `_VIEWS_PER_SEG = 3` 個子段(bucket 切法 `[0,1,2] / [3,4,5] / [6,7]`)。
子段 0 維持原圖,子段 1、2 各換成**同一檔股票的另一種真資料圖**,子段內自己從 35% 揭露到 100%。

候選圖種:`history` / `fundamentals` / `valuation` / `drawdown` / `trend` / `dca`。
起點按 `seg_idx` 錯開,並優先挑**全片還沒出現過**的圖種(`used_view_keys`)。

機制示意圖(`grid` / `compound` / `martingale`)**刻意不列入候選**:它們對任何標的都畫得出來,
換過去等於「圖變了但沒多給這一檔的資訊」,而且和本段旁白無關。

## 2. 事實庫硬規則怎麼落實的

不另寫一份「這檔有沒有這組資料」的檢查 —— 那份會和真正畫圖的那份分岔。
`_view_probe` 直接用 480×270 縮圖**實跑同一支正式 drawer**,回 `None` 就是畫不出來,那個視角就不採用。

缺資料時的退化行為:該子段不換 → `_bs` 退回 `range(8)` → 揭露比例用**整段連續**那把尺
= 與換視角前逐字相同的行為。所以「事實庫沒資料」的路徑輸出和改動前完全一致,不是另一條新路徑。

### 每一種換進來的圖,數字出自哪個欄位

| 圖種 | 資料來源 | 具體欄位 |
|---|---|---|
| `history` / `trend` / `drawdown` / `dca` | `STUDIO/tw_facts_cache/<代號>.csv` | 真實日收盤序列(`concept_visuals.py:63` `_FACTS_CACHE`) |
| `fundamentals` | `STUDIO/stock_checkup_facts.json` | `checkup_revenue_trend__<代號>.data.series[].year/revenue`、`checkup_eps_trend__<代號>.data.series[].eps` |
| `valuation` | `STUDIO/stock_checkup_facts.json` | `checkup_valuation_position__<代號>.data` 的 `p25 / median / p75 / latest_per / percentile_rank` |

六支 drawer 拿不到上述欄位一律 `return None`,沒有任何一支會用亂數頂替(`concept_visuals.py` `_DISPATCH` 註解)。

## 4. 兩個指標(人眼看 contact sheet 判定)

判定規則(before / after 用同一把尺):
- **一張「來源圖」** = 連續一段時間內人眼看到的是同一張底圖在逐步揭露(圖種相同、配色相同、
  圖說敘述屬同一組)。換成明顯不同的另一張圖才算下一張。
- **不重複來源圖張數** = 全片切出來的圖段中**互不相同**的張數(同一張圖出現兩次只算一次)。
- **單圖最長停留秒數** = 任一張圖連續出現的最長秒數(相鄰且人眼判為同一張則合併計算)。

**刻意不用 scene detection / 像素差**:揭露動畫每一格像素都在動,但來源圖只有一張 ——
那量到的是「畫面有沒有動」,不是「這是不是同一張來源圖」。`sheet.py` 只負責抽幀攤平標時間,判斷全交人眼。

取樣 10 秒一幀,所以停留秒數解析度 ±10s。

| 股票 | 片長 | 不重複來源圖張數 before→after | 張/分鐘 before→after | 單圖最長停留 before→after |
|---|---|---|---|---|
| 2891 中信金 | 10.37 min | 4 → 5 | 0.39 → 0.48 | 150s → ~50s |
| 1560 中砂 | 11.85 min | 4 → 6 | 0.34 → 0.51 | 150s → ~70s |
| 5274 信驊 | 7.21 min | 5 → 6 | 0.69 → 0.83 | 150s → ~40s |

**「不重複張數」漲幅有限,這是真的,原因要寫清楚**:全片不重複張數的天花板 = 事實庫對這檔畫得出來的
圖種數。2891 只有 4 種(見第 5 節),所以 4→5 就差不多到頂了。真正動起來的是**畫面換圖的頻率**:

| 股票 | 圖段數 before→after | 圖段/分鐘 before→after |
|---|---|---|
| 2891 | 5 → 15 | 0.48 → 1.45(3.0×) |
| 1560 | 6 → 18 | 0.51 → 1.52(3.0×) |
| 5274 | 7 → 21 | 0.97 → 2.91(3.0×) |

三支片的 BEFORE 單圖最長停留都落在 ~150s,和診斷報告講的「~126 秒一張圖」吻合;AFTER 降到 40~70s。

對照圖:`contact_sheets/before_*.jpg` vs `contact_sheets/after_*.jpg`(同一取樣規則、同一版面)。

## 6. 會叫的檢查

`check_子段切分不變量.py` —— 驗 `_reveal_view_buckets(view, V, N)` 的不變量:每個 bucket 一定在
自己算出來的那個 view 的清單裡。破了的話 `_reveal_base` 的 `.index(bucket)` 會丟 `ValueError`、
被外層 `except` 吞掉 → **整片揭露圖靜默退回原卡,沒有人會看到錯誤**。

最後一格是陽性對照(故意餵一個等分切的壞實作),檢查必須抓到它,否則整支 exit 1。

```
[check] render_ffmpeg <- ...\render_ffmpeg.py
  ✓ 正式實作
  (以下是陽性對照,必須被抓到)
  ✗ 故意寫壞的等分切: V=2 N=3 bucket 1 被放進 view 1
實作通過=True 陽性對照有抓到=True
V=3 N=8 實際切法: [[0, 1, 2], [3, 4, 5], [6, 7]]
```

## 7. 順帶確認沒被弄壞的

**數字爆現(上一輪的 fail-closed 閘門)**:sidecar 找的是 `reveal_{seg:02d}_{bucket}.png.meta.json`,
dest 檔名仍由 (seg_idx, bucket) 決定,所以自動跟著換視角走。三支片 before / after 都是
`數字爆現:4 個 overlay`,沒有因為圖說換了而被閘門多擋掉。

**`_series_force_key`**:只在沒換視角(`fkey is None`)時才生效,行為與改動前相同。

**沙箱對正式機的副作用**:沙箱的 `STUDIO` / `assets` 是指向正式目錄的 junction。渲染路徑只會
append `STUDIO/ops_log.txt`(心跳),不寫任何正式狀態檔(`checkup_ep_ledger` 等由排程器 `local_cron` 寫,
不是渲染路徑)。沒有重渲/重傳任何已上架影片,沒有發布,沒有動排程設定。

## 8. 已知取捨(留給獨立驗收判斷,我沒有動它)

段落頂部大標題在整段內不變,但底下的圖換了圖種 ⇒ 會出現「大標寫『估值位置』、圖畫的是定期定額」
這類標題與圖對不上的畫面(例:`after_2891.jpg` 545s、`after_5274.jpg` 85s)。

兩件事讓我決定**不動它**:
1. 這不是換視角引進的新缺陷 —— 改動前就有,而且很常見(`before_2891.jpg` 495s 大標「估值位置」
   配的是紅色走勢圖不是估值圖;`before_1560.jpg` 565s 大標「量化投資的核心」配定期定額圖)。
   換視角只是提高了出現頻率。
2. 每張圖自己的圖說會寫清楚畫的是什麼,上一輪的數字爆現閘門也是拿旁白數字去對圖說,
   所以**數字誠信不受影響**,受影響的只是標題與圖的語意貼合度。

要修的話成本不低(得在子段邊界重繪 HUD 標題條),而且會動到 HUD 合成路徑 —— 那超出本次範圍。
建議由獨立驗收判斷這個頻率是否可接受,再決定要不要開下一輪。
