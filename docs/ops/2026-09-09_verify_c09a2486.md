## 一、承重前提:**成立**,而且射程比原本講的更寬

`pythonw.exe` 排程下 `sys.stdout` / `sys.stderr` **兩個都是 `None`**;
`print(file=sys.stderr)` 靜默 no-op、`sys.stderr.write` 拋 `AttributeError`、寫檔是唯一通道。

驗法(兩條獨立路徑 + 陰性對照,缺一不可):
- (a) `Start-Process pythonw`(**刻意不用**實作者的 `DETACHED_PROCESS`,換一條路):兩個都 None,Win32 `GetStdHandle` 三個都是 0
- (b) **真的註冊一個 Windows 排程工作**(principal 抄 `carson-seeding-watch`:User/Interactive/Limited),`LastResult=0`,結果與 (a) 逐項一致。跑完刪掉,`schtasks /Query` 兩個都回 "cannot find the file specified"
- 陰性對照:同一支探針在**互動終端**跑 → `stderr` **不是** None(TextIOWrapper cp950),三條探測訊息全部看得見 ⇒ 探針有鑑別度,不是對什麼都說 None

### 🔴 `python.exe` 是**第三種**形狀,比預想的更難抓

排程下的 `python.exe` **拿得到有效 handle**(224/228/232),指向一個**新配、沒有人看得到的 console**。
⇒ 不是 None、不拋 `AttributeError`、`print` 完全成功 —— **寫進去就消失,而且沒有任何一層會抱怨**。

⇒ 三種形狀要分開講,不可以合併成「排程下 stderr 沒用」:

| 環境 | `sys.stderr` | 症狀 | 抓得到嗎 |
|---|---|---|---|
| 互動 / `local_cron` job | 正常 | 到得了讀者 | — |
| 排程 + `pythonw.exe` | `None` | `print` no-op、`.write` 拋例外 | 拋例外那次會被注意到 |
| **排程 + `python.exe`** | **有效 handle** | **寫成功,然後蒸發** | 🔴 **完全無聲,連例外都沒有** |
