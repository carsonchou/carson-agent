## 一、能不能分來源拿:不能,而且我證明了不是我打錯

不從文件推,直接打 API 收伺服器原話:

| # | 查詢 | 結果 |
|---|---|---|
| ① | `audienceWatchRatio × elapsedVideoTimeRatio`(現行做法) | ✅ 100 個點 |
| ② | filters 加 `insightTrafficSourceType==YT_SEARCH` | ❌ **`The query is not supported.`** |
| ③ | 同上但不帶 `audienceType` | ❌ 同樣訊息 |
| ④ | dimensions 加 `insightTrafficSourceType` | ❌ 同樣訊息 |
| ⑤ | **陽性對照**:filters 加 `subscribedStatus==UNSUBSCRIBED` | ✅ 100 個點 |
| ⑥ | `insightTrafficSourceType × averageViewPercentage`(非曲線) | ✅ 可用 |

⑤ 是必要的:沒有它,「②③④ 被拒」和「這個端點對任何額外篩選都會拒」分不開。

🔴 **而 ⑤ 吐出和 ① 完全一樣的數字(0.9337/0.8783/0.8228/0.5655),我一度懷疑它是「接受但靜默忽略」。**
去做鑑別測試:

```
UNSUBSCRIBED  rows=100  前4=[0.9337, 0.8783, 0.8228, 0.5655]
SUBSCRIBED    rows=0    前4=[]
(無篩選)       rows=100  前4=[0.9337, 0.8783, 0.8228, 0.5655]
實際分佈: UNSUBSCRIBED 708 觀看 / SUBSCRIBED 0 觀看
```

⇒ 篩選**確實生效**(SUBSCRIBED 回 0 列,而實際就是 0 觀看),數字相同是因為這支片的觀眾 100% 是非訂閱者。
**不是靜默忽略,陽性對照成立。**

📌 副產品:這支片 `SUBSCRIBER` **來源**有 522 觀看,而 `subscribedStatus` 是 **0 個訂閱者** ——
在單支片的層級獨立重現了總督導的交叉表結論:**`SUBSCRIBER` 這個來源標籤不是「我們的訂閱者」。**

## 五、那條 memory 該不該改:要改,但方向不是「推翻」

`yt-retention-is-audience-not-content` 說「留存由觀眾來源決定,非內容」,三次獨立重現。
旗艦提案的反對是:那三次的母體裡**每一支片都是同一個模板** ⇒ 它分不出
「內容不影響留存」和「我們的內容從來沒變過」。

**這次的量測讓兩邊都站得更穩,而它們並不衝突:**

1. **memory 的核心宣稱被強化了。** 片內配對(內容完全是常數)仍然量到 3.4~3.9 倍差距,
   t=3.59,遠大於 MDE。**來源效應是真的、很大,而且這是最乾淨的一次量法。**
2. **旗艦提案的反對也成立,而且現在有了具體形狀。**
   分歧集中在 **15~55 秒**,而那 40 秒放的是系列自我介紹與公司簡介樣板 ——
   **在既有母體裡,那一段從來沒有被有意義地變動過。**
   ⇒ 「內容不影響留存」這句話**在那個窗口上從來沒被測過**,
   因為那個設計結構上量不到一個從沒變動過的變數。

⇒ **要補的不是結論,是射程。** 建議把 memory 的 description 補一句:
> ⚠️ 這條的射程是「**片長**不是槓桿」與「來源效應很大」,**不是「內容不是槓桿」**。
> 09-08 片內配對再次確認來源效應(3.4×,內容為常數);
> 但同一批資料顯示差距集中在 **15~55 秒**,而那一段在既有母體裡從沒變過
> ⇒ 內容效應**沒有被測過**,不可以拿本條當「改內容沒用」的依據。

**我沒有直接改那個 memory** —— 它是主頻道線在承重的,而且「該不該改」本身是判斷不是量測。
上面那段是建議文字,等你或主頻道線點頭。

## 六、值多少(上限,不是預估)

- 現況:首頁動態 22,647 觀看 × 0.69 分/觀 = **15,626 分/30 天**
- 15~55 秒的比值從 0.99 掉到 0.65。若**那一段的差距完全消掉**,55 秒之後的曲線整條 × (1/0.65) ≈ 1.54
  ⇒ 0.69 → **約 1.06 分/觀**,增加 **約 8,400 分/30 天 = 140 小時/30 天**

⚠️ **這是上限,而且是一個我自己的資料不支持的上限。**
片內配對顯示「內容為常數時仍有 3.4 倍差距」⇒ **這個 gap 的大部分是觀眾不是內容**。
可歸因給內容的那一份**無法用觀察資料切出來**,只能做實驗。

## 七、所以該做什麼實驗(這是唯一能分開兩者的方法)

**變動第 15~55 秒,量首頁來源的留存。** 這是第一個能分辨的實驗,因為那是第一次那一段會變。

- **處置**:把系列自我介紹 + 公司簡介樣板從 15~55 秒拿掉,直接進入第一個具體數字
- **對照**:同期同題材、維持原結構
- **應變數**:🔴 **`estimatedMinutesWatched`,不要用 `views`**
  (memory `yt-traffic-source-ceiling-2026-08`:用 views 會做出反向決定)
  ;曲線層級看 15s / 55s 兩點的 watch ratio
- **樣本**:首頁群單支中位觀看約 200~700,依第四節的 SE,單支噪音太大
  ⇒ **要以「支」為單位配對,至少各 15~20 支**才壓得到 MDE 0.13 以下
- ⚠️ **不要只看整體平均**:整體會被搜尋流量稀釋(搜尋群的同一個效應只有 +0.053)。
  要分來源看,而分來源的**水位**拿得到(第二節),雖然分來源的**曲線**拿不到

## 八、母體偏誤:交辦時點名的那件,確認了

`retention_probe.py` 的母體是雙重篩選:
- `:93` `sort="-estimatedMinutesWatched", maxResults=200` ⇒ **Top-200 截斷**
- `MIN_VIEWS = 120` ⇒ 再砍一刀

⇒ 那 16 條曲線**偏向高表現的片**,不能當全頻道的代表。
**本報告沒有用那 16 條**;所有曲線都是這次現抓的,母體來自 `uploaded_ledger` 全量 305 支長片,
再用「單一來源 ≥80% + 觀看 ≥200」篩出對照組 —— 那個篩選是**為了對照組純度**,
不是為了表現,而且兩群的題材組成有列出來供檢查。

## 九、方法論

1. **「不支援」要拿伺服器原話,而且要有陽性對照。**
   ②③④ 全部被拒時,我還不能說「API 不支援」——要先證明這個端點不是對任何額外篩選都拒。
   ⑤ 通了,才把「不支援」從推測變成結論。
2. **「接受」不等於「生效」。** ⑤ 吐出和無篩選一模一樣的數字,長得就像被靜默忽略。
   分辨它的是**問相反的那一邊**(SUBSCRIBED → 0 列)加上**去查實際分佈**(確實 0 觀看)。
   只問一個方向,「篩選有效」和「篩選被忽略」在觀測上相同。
3. **片間對照要先報題材組成,再談形狀。** 兩群都是九成個股體檢,這個報告才成立;
   如果一群是體檢一群是教學,正確的結論是「量不出來」。
4. **三個例子不是證據。** 我看完三支 `.srt` 就要寫「那 40 秒是模板固定的自我介紹」,
   量下去是 53%,不是 100%。**例子的說服力和它的代表性無關**,而例子是自己挑的。
5. **t 值過線不等於量得出來。** 群內對照 t=2.64 看起來成立,但觀測效應 0.124 < MDE 0.131
   ⇒ 這個樣本量偵測不到這個大小的效應,點估計很可能被高估。
   **要同時報 t 和 MDE;只報 t 會把「剛好抽到」講成「發現」。**
6. **一個「被強化的結論」和一個「射程被限縮的結論」可以同時發生。**
   來源效應被這次量得更穩,而同一批資料同時顯示那條 memory 被用在它沒量過的地方。
   ⇒ 推翻與補射程是兩件事,**混為一談會讓正確的結論被整條丟掉**。
