# premises.md — 跨線承重假設登記處

**要拿一個假設當承重點之前,先掃這份。**
**你動搖了任何一條(包括更正自己的小數字),回來改它,不是只改自己那條線。**

為什麼有這個檔:git log 只看得到已完成的改動,看不到**正在被動搖的假設**;跨線撞車幾乎都發生在後者(實例:配額申請書拿「多發更多片」當承重點的同一晚,main ch. 正在驗的結論是「現有資料回答不了,甚至可能相反」)。

## 守則(總督導裁定,不准放寬)

1. **只登記承重假設,不是待辦。** 判準:這個假設翻了,是不是有**另一條線**要整個重做?不是就不進。永遠 ≤10 條。
2. **每條必有「驗收日期」和「誰在驗」**,沒有驗收日期的不准進。
3. **一行一條**,整份可以一眼掃過;不准長成每條一節的文件。
4. **等待條件要主動複驗**:任何「等 X 重置/等 Y 回覆/等 Z 出結論」,每次回到工作先驗那個條件是不是早就成立了——等待條件不會自己通知你它已滿足(實例:09-02 早上還在等 8 小時前就已重置的 session 限額;09-01 晚等 Carson 回「herdr 順了嗎」而停住)。
