## 2. 設計原則(沿用本頻道已踩過的坑,逐條標來源)
1. **母體會自己長大,不准用「加例外」解**——84 campaign 自己的解法是凍結 DONE 快照到 sha1,兩支回填工具的候選清單同樣是持續成長的帳本(每日 15:05 cron 母體滾動),必須比照凍結,不比照加白名單。
2. **CAS 寫入(tmp→readback→os.replace)是全庫規則,不分正式機/memory/scratchpad**——兩支回填工具目前違反,這是**進場前必須先補的地板**,不是可以留到之後的 nice-to-have(memory `write-truncates-before-it-fails`、`rule-scope-not-narrowed-by-the-bound`)。
3. **安全網不能先於它保護的動作被驗證**——84 campaign 自己的還原工具目前也只驗過合成 fixture(因為真實 `*.pre_rewrite.json`/STAMP 都是 0 筆),把兩支從沒寫過一筆的回填工具疊上去,等於在一個**自己也沒被真實驗證過**的機制上再加兩層未驗證的東西。這是本提案建議「先跑通 84 campaign 至少一次真實 canary,再談回填併入」的直接依據(見 §4)。
4. **檔名慣例衝突要在動手前消掉,不要留到出事才發現**——`.pre_rewrite.json` vs `<vid>.json` 已被研究 agent 點名同目錄可能互相覆蓋/誤讀,兩邊都要改成同一命名規則。
5. **識別碼/凍結基準不准用猜的**——140 vs 185(章節)、89 vs 28(字幕)這兩組數字對應到不同基準檔,本文件不替 wF:p3 選一個,列成待裁決項(§3)。
