## 三、殘留盲區(有界、目前休眠)

**`calls < 50` 的高比例被拒不會叫。**

- 傷害上限:49 次便宜呼叫 = 49 units = 配額的 **0.19%**。貴呼叫
  (`search` 100 / `videos.insert` 1600)會被「浪費 > 牆的 10%」那條接住。
- 真帳本 10 天的 calls 分佈:`63 / 145 / 182 / 211 / 234 / 287 / 305 / 334 / 337 / 440`。
  **最低 63,離 50 只有 13 的餘裕。**
- 🔴 **停產日會掉下去** —— memory `yt-topic-bank-burned-by-regen` 記過停產 7 小時的前例。
  那種日子 calls 可能不到 50,盲區就從休眠變成生效。

**驗證員給的補法(未實作,留給下一個動這段的人)**:
把 `_cal >= 50` 換成 `_rej > 20 and _rej > _cal * 0.50`。
`calls >= 50` 這個下限當初是為了擋合成測試常見的 `calls=1`(前幾輪 harness 就是),
換成「被拒絕對數 > 20」可以同時擋掉那個又不放過低量日。

這是**有界且休眠**的洞,和第四輪那種「砍 31% 無限期靜音」不同 —— 那個是無界的。

## 五、一個前提已解:半截檔防護防的是真情境

驗證員五輪都把「`save_json_atomic` 到底原不原子」列為未查證。已查:

- `studio_common.save_json_atomic`(`scripts/studio_common.py:42`)**是原子的** ——
  寫 `.tmp`(帶 pid+thread 唯一化)→ `os.replace` 同目錄原子替換,
  含 Windows `PermissionError` 重試 10 次。
- 🔴 **但 `quota_meter._save()` 有一條非原子退路**:原子寫拋例外時,
  `except` 裡直接 `STATE.write_text()` 寫**最終路徑**。
  而原子寫正是在「目標檔被別的進程佔用、重試十次後」才拋 —— 也就是說,
  **併發最嚴重的那一刻,正好是退路生效、非原子寫上場的那一刻。**

所以 `91c3e248` 加的半截檔偵測防的是**真情境**,不是假想。此前提已解,不要再列為未知。
(修 `_save()` 那條退路屬於 `quota_meter.py`,在總督導的待修佇列裡,不歸這條線。)
