## 五、方法論(唯一會隨 context 消失的)

1. **陰性對照要用真實觸發過的那一次**(見一.2)。合成的 fixture 只證明得了 fixture。
2. **別人留在輸入框的草稿:`send-keys Enter` 推不動,`send-text` 一碰就毀,只有 `herdr agent prompt` 送得出去。**
   ⇒ **動它之前先逐字抄下來留在自己的訊息裡。** 我今天毀掉過一份 Carson 的授權,
   靠事先抄下來才補送回去。而「送出了」和「被清掉了」畫面上一模一樣(都是空的 `❯`),
   要看三樣:status 有沒有變 `working`、逐字稿末尾有沒有多一則 user 訊息、計時器有沒有重新開始。
3. **裸的 `herdr pane process-info` 回的是焦點窗格,不是你自己。** 我一度以為自己是 wF:p5。
   認自己要拿 session id 去比對 `herdr agent list`。
4. **`/clear` 換一個新 session id,而 cmdline 的 `--resume` 停在啟動那次** ⇒ 窗格對照表每被 /clear 一次失效一格。
5. **我的檢查問錯過問題**:斷言「這串字不在檔案裡」,而原句是**刻意**留在撤回標記裡的 ⇒ 報 FAIL。
   該問的是「每一處出現是否都帶撤回標記」。`verification-that-cannot-fail` 的「執行正確但問錯問題」。
6. **單位口徑**:門檻 `5_000_000` 是十進位,拿 5 MiB 算會得到 84.3% 而不是 88.4%
   —— **差那 4 個百分點就是「還有幾天」和「快到了」的差別**。
7. **改產線檔要驗「行為零改變」不是「我只改了註解」**:AST 逐字比對 HEAD vs 工作區,
   並帶陽性對照(塞一行真程式碼進去,確認比對器會叫)。今天用了三次。
