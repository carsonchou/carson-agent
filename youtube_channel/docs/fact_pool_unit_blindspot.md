# fact_pool 單位盲區 — 診斷與遷移交接書

> 建立 2026-07-17｜狀態:**已診斷、刻意未修**｜對象:下一個要動 `scripts/fact_source_guard.py` 的人
> 一句話:**守門的數字池沒有單位,所以「多賺 37 萬」被池裡的「37.1%」佐證了。數字對得上 ≠ 有憑據。**

## 0. 這份文件為什麼存在

2026-07-17 稽核未發布片時,兩支明天就要發的片(`S_EP6美股VTI…多繳3.2萬`、
`S_EP1台積電600元…5年後差37萬`)的數字在**五個事實庫全查無來源**,卻**通過了發布端誠信守門**。
守門(`fact_source_guard`)**有**接進 `daily_publish.py`(fail-open)、**也有**金額 pattern,卻完全沒攔。
追根究柢不是「漏看」,而是**它看見了、而且判定有憑據——那是假佐證**。這比漏網嚴重:**它在替假數字背書。**

## 1. 根因:池是「無單位的 float 集合」,宣稱卻是「有單位的」

`fact_pool()` 把五個事實庫(`FACT_FILES`)裡**所有**數字用 `_walk_numbers()` 攤平成一個
`set[float]` —— **2446 個數字,單位全部丟掉**。池裡混著:

| 池裡實際混進的東西 | 例 |
|---|---|
| 百分比/年化/回撤 | 762.7、24.0、-33.8 |
| 本益比、殖利率 | 8.5、8.23 |
| 年份、年數 | 2014、10.0、12.5 |
| 卡瑪比率、夏普 | 0.64、4.7661 |
| 檔數、交易筆數 | 1925、13 |

而「多賺 **37 萬**」是**金額**。`_sourced()` / `_sourced_strict()` 只做 `abs(f - val) <= tol` 的**純數值比對**,
**不看單位** → 37(萬)撞上 37.1(%)就算「有憑據」。

### 三道逃逸(任一道成立,假數字就過關)

1. **一般句的金額根本不抽**
   金額 regex `_RX_NUM_IN_ATTR` **只在「假掛名句」內跑**(`_ATTRIBUTION` = 回測顯示/數據顯示/實測結果…12 個詞)。
   EP1 的「反而多賺三十七萬」沒有假掛名詞 → **完全在雷達外**。
   ⚠️ 這是**刻意取捨**,不是 bug(原註解:金額在一般句可能只是本金舉例「每天當沖兩百萬」,誤擋成本高)。
2. **🔴 就算進了假掛名句,池不分單位 → 金額撞百分比**(最隱蔽,**它看起來有溯源**)
   `extract_claims()` 在假掛名分支有一道預過濾:`if _sourced_strict(val, fact_pool()): continue`。
   金額撞上池裡不相干的百分比 → **在抽取階段就被丟掉,claim 根本不會產生**。
3. **單位表本身有缺口**
   `_RX_NUM_IN_ATTR` 的單位 = `(萬|億|倍|次|檔|支|%)` → **沒有「元」「年」「分」**。
   「600元」「5年」「99分」永遠抽不到(即使池裡沒有鄰居也一樣逃)。
4. (次要)`HEDGE` 的 **「假設」** 會放行整句:EP6「**假設**每月投入1萬…多吃掉3.2萬」。
   但前三道已先漏,這道排不上用場。

## 3. 規模詛咒:**池越大,守門越弱**(設計上的反直覺陷阱)

`fact_source_guard.py` 原註解已記載過一次(2026-07-14,全市場軍火入池後池 431→1154,
「AI機器人90%虧損」撞 89.1、「少賺38萬」撞 38.9),當時的補強是**嚴容差 + 整十數規則**。
**但那只治了症狀,沒治根因** —— 根因是池無單位。今天池已 **2446** 個:

- 兩位數金額的嚴容差窗 ≈ ±0.25 → 在 0~100 區間,池裡幾乎必有鄰居
- 實測 37 / 3.2 / 65 **三個全部撞上**,只有 600(三位數、窗 ±3.0、但池在該區稀疏)沒撞

**推論:每次把新事實灌進事實庫(這是好事、是我們一直在做的事),守門就自動變弱一分。**
這是**反直覺**的:直覺以為「事實庫越豐富 → 溯源越可靠」,實際是「池越密 → 任何編造數字越容易找到鄰居」。
**這條必須寫在任何『擴充事實庫』的 PR 檢查表裡。**

## 4. 修法建議 + **為什麼現在不能修**

### ❌ 錯誤修法(會主動造成傷害,別做)

**「把『元』『年』『分』加進 `_RX_NUM_IN_ATTR` 單位表」** —— 這是最直覺、也最錯的修法。
實測:待發 13 支裡有 **8 支**含「金額/倍/年」落在績效語境,而其中多數是**合法的**:

| 片 | 命中 | 真相 |
|---|---|---|
| L_鴻海2317翻7.3倍 | `二十年` `七點三倍` `九年` | **合法**:checkup 625.1% → 7.25x,「倍」是正確衍生 |
| L_中華電2412翻5.1倍 | `二十年` `五點一倍` | **合法**:checkup 407.9% → 5.08x |
| S_EP8台積電 | `2026年` `26年` | **期間**,不是績效宣稱 |
| S_EP9 00929 | `三年` ×4 | **期間**,不是績效宣稱 |

**加「年」= 把期間當績效宣稱擋掉 → 誤殺一片。** 這證明問題不在單位表,在**池沒有單位**。

### ✅ 正確方向:**讓池帶單位**(unit-aware pool)

1. `_walk_numbers()` 改成 `_walk_typed_numbers()`,產出 `set[tuple[float, unit]]`,
   unit 從**欄位名/上下文**推斷:`total_return`/`cagr`/`max_drawdown` → `pct`;
   `years`/`period` → `year`;`calmar`/`sharpe` → `ratio`;`num_trades` → `count`。
2. `_sourced(val, unit)` **只在同單位子池內比對**。`pct` 子池比現在小一個量級 → 規模詛咒同步緩解。
3. 宣稱端 `extract_claims()` 同步標 unit(`37萬`→`amount`、`24%`→`pct`、`7.3倍`→`multiple`)。
4. **`amount` 單位在事實庫裡根本沒有對應子池**(五個庫全是報酬率/比率,沒有任何「萬元」金額)
   → 邏輯上**任何金額宣稱都必然無憑據**,除非它是文本內合法算術(如 100萬×報酬率)。
   這也解釋了為什麼 EP1/EP6 是**結構性**的無憑據,不是個案。

### ⚠️ 本節原本的結論是錯的 —— 2026-07-17 實測更正(commit 76a43d1)

> **原文寫「現在不能修,會停產」。那是把兩個變數混在一起量出來的,後來被實測推翻。
> 若你讀到這裡準備放棄修它 —— 不要,先看下面的表。**

實作觀測模式後把兩個變數**分離**再量:

| 方案 | 待發 9 支誤殺 | 全語料 334 支誤殺 | 抓得到 EP1 嗎 |
|---|---|---|---|
| **A：只把池單位化**(本文原本主張的「正解」) | **0** | **1** | ✗ |
| A+B：單位化 **併同**擴大抽取面 | 1 | **85(25%)** | ✓ |

- **「停產風險」量到的其實是 B(擴大抽取面),不是 A。A 誤殺 0 支,停產風險實測不存在。**
- A 擋下的那 1 支**不是誤殺,是真憑據問題**(已發布的漂移片)。
- 原文「待發 13 支中 8 支含金額/倍/年」屬實,但**那是 A+B 才會重新檢視的範圍**;A 碰不到它們。

### 🔴 更重要:**A 治不了 EP1/EP6 —— 單位化不是本案的根因**

本文開頭把 EP1/EP6 當成「單位盲區」的代表案例,**那個歸因是錯的**:

- **EP1**(「反而多賺三十七萬」):**沒有假掛名詞 → 壓根沒進抽取器**(逃逸 #1),
  單位化在它後面,碰不到。
- **EP6**:子句**無 PERF_CTX 詞**(「吃掉」不在成本語彙表)→ 不算績效宣稱;
  **且**被 HEDGE「假設」救援整句。**兩道都在單位之前。**

**真根因是 `PERF_CTX` 成本語彙不全 + `HEDGE`「假設」救援過寬**,不在單位表、也不在本文原本的修法清單裡。
單位化(A)是**低風險低報酬**的一道:值得上(誤殺 0),**但上了不等於 EP1/EP6 已修**。

### 更正 `amount` 子池的描述

原文說「五個庫全是報酬率、沒有金額子池」——**不精確**。實測 `amount` 子池**有 14 個值**,
但**全是營收級距**(最小 ≈ 416 億);另有 `price_twd`=269、`amount_twd`=69。
**結論仍成立**(無個人損益級距 → 「37 萬 / 3.2 萬」必然無憑據),但**理由要改成「沒有對應量級的子池」,不是「沒有子池」**。

### 安全遷移順序(建議)

1. **先加觀測,不改判定**:`--report` 模式輸出「若單位化會新增擋下哪幾支」,跑 1-2 週對帳,人工複核誤殺率。
2. **先補 `unit` 標註到事實庫產生端**(`tw_facts_engine` / `stock_checkup_facts` 寫入時就帶單位),
   而不是在守門端猜 —— 猜單位會製造第二個 drift 源(同 legacy 的教訓)。
3. **先讓合法算術過關**:金額若由「文本內已溯源的百分比 × 文本內本金」算得出 → 放行(擴充 `_diff_ok` 為 `_calc_ok`)。
4. **最後才把單位比對接上 fail-closed**,且**先只對 `amount` 類生效**(影響面最小、且該類結構上必然無源)。
5. 全程保留 fail-open 的 except 兜底,絕不讓守門例外導致產線停擺。
